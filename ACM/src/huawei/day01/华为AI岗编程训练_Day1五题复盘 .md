## 二、第 1 题：模型推理量化加速优化

### 1. 题型识别

模型有若干层，每层有多个量化方案：

- 每一层必须且只能选择一个方案；
- 每个方案有精度损失 `loss` 和显存占用 `memory`；
- 总精度损失不能超过阈值 `T`；
- 求最小总显存。

去掉 AI 背景后，这是一个典型的**分组背包最小化问题**：

- 每层是一个组；
- 每组必须选择一个方案；
- 损失是容量；
- 显存是需要最小化的代价。

### 2. 我的第一版思路

我先使用 DFS 枚举每层选择的方案：

```java
dfs(i, target)
```

表示处理到第 `i` 层，在剩余损失额度为 `target` 时的最小显存。

这一版已经抓住了最核心的约束：**每层必须选择一个方案**。在每层枚举所有方案，然后递归处理前一层。

### 3. 第一次没有想到或出错的地方

#### 错误一：小数不能直接作为 DP 数组下标

输入的精度损失可能是 `0.1、0.25` 等小数，数组下标只能是整数，因此不能直接创建：

```java
dp[n + 1][T + 1]
```

解决方法是根据题目小数位数进行等比例放大：

```java
int t = (int) Math.round(inputT * 100);
int loss = (int) Math.round(inputLoss * 100);
```

这里必须使用 `Math.round`，不能简单强制类型转换，否则浮点误差可能使：

```java
(int) (0.29 * 100)
```

得到 `28`。

#### 错误二：DP 数组默认值为 0，破坏了“最小值”状态

我第一次创建二维数组后没有将非法状态初始化为正无穷。Java 的 `double[][]` 默认都是 `0.0`，于是：

```java
Math.min(0, 合法方案显存)
```

永远会保留 `0`。

对于“求最小值”的 DP，尚未到达的状态必须初始化为：

```java
Double.POSITIVE_INFINITY
```

然后只设置唯一合法起点：

```java
dp[0][0] = 0;
```

#### 错误三：没有区分“损失恰好为 j”和“损失不超过 T”

定义：

```text
dp[i][j] = 前 i 层恰好产生 j 点损失时的最小显存
```

因此最终答案不是固定的 `dp[n][T]`，而是：

```text
min(dp[n][0], dp[n][1], ..., dp[n][T])
```

因为题目要求的是损失**不超过** `T`，而不是必须恰好等于 `T`。

#### 错误四：必须阻止非法状态参与转移

只有 `dp[i][j]` 可达时，才能从它继续选择下一层方案：

```java
if (Double.isInfinite(dp[i][j])) {
    continue;
}
```

虽然某些写法中无穷大加有限值仍然是无穷大，不一定影响结果，但主动判断可以使状态含义更清楚，也能避免使用整数 `INF` 时发生溢出。

### 4. 正确状态设计

```text
dp[i][j] = 前 i 层的累计损失恰好为 j 时，最小显存占用
```

初始化：

```text
dp[0][0] = 0
其他状态 = +∞
```

状态转移：

```text
dp[i + 1][j + loss[i][k]]
    = min(dp[i + 1][j + loss[i][k]],
          dp[i][j] + memory[i][k])
```

每次从第 `i` 层的所有可达状态出发，枚举当前层的一个方案。由于从 `dp[i]` 转移到 `dp[i+1]`，自然保证每层恰好选择一次。

### 5. 本题复习关键词

- 分组背包
- 每组必须选一个
- 小数乘倍数后离散化
- `Math.round`
- 最小值 DP 使用正无穷初始化
- 唯一合法起点 `dp[0][0]`
- 答案是所有 `j <= T` 的最小值

## 三、第 2 题：最大能量路径

### 1. 题型识别

题目包含两个阶段：

1. 使用策略矩阵计算图像中每个位置的能量；
2. 从第一列走到最后一列，每次只能右上、正右、右下，求路径最大能量。

算法本质是：

- 第一阶段：带零填充的二维卷积式模拟；
- 第二阶段：网格路径动态规划。

### 2. 我的第一版思路

我正确地将问题拆成了两部分：

1. 先计算完整的能量矩阵 `E`；
2. 再在 `E` 上进行记忆化搜索。

定义：

```java
dfs(r, c)
```

表示以 `(r,c)` 为终点，从第一列走到这里能够获得的最大能量。

状态来自左上、左侧和左下三个位置：

```text
dfs(r,c) =
E[r][c] + max(
    dfs(r-1,c-1),
    dfs(r,c-1),
    dfs(r+1,c-1)
)
```

这版代码在 CodeFun 上全部通过，说明整体拆分、公式实现和状态方向是正确的。

### 3. 本题值得警惕的地方

#### 风险一：注释中写成“取最小值”

代码实际使用了最大值，但注释写了：

> 状态来自三个方向转移来取最小值

这类注释与代码不一致，复盘或修改时容易误导自己。题目求最大能量，必须取最大值。

#### 风险二：越界返回 0 依赖数据条件

代码中行越界时返回 `0`：

```java
if (i < 0 || i >= e.length) return 0;
```

如果能量可能是负数，这会把“非法越界路径”当成一条能量为 `0` 的合法路径。此时算法可能宁愿越界，也不选择负数的合法前驱。

更稳妥的做法：

```java
return NEG_INF;
```

只有到达第一列之前的合法终点，才能返回 `0` 作为递归起点。

不过，如果原题明确保证能量非负，那么返回 `0` 不会影响答案。考试中应根据数据范围判断，不能默认。

#### 风险三：缓存使用 `-1` 作为“未计算”

如果合法最大能量可能恰好为 `-1`，那么 `-1` 不能同时表示未计算。更稳妥的方式有两种：

- 单独使用 `boolean[][] visited`；
- 将缓存初始化为一个不可能出现的特殊值。

#### 风险四：答案初始值设为 0

```java
double ans = 0;
```

如果所有路径能量均为负数，最终会错误输出 `0`。应初始化为：

```java
int ans = Integer.MIN_VALUE;
```

### 4. 递推 DP 写法

可以定义：

```text
dp[r][c] = 从第一列走到 (r,c) 的最大路径能量
```

第一列：

```text
dp[r][0] = E[r][0]
```

后续列：

```text
dp[r][c] = E[r][c] + max(
    dp[r][c-1],
    dp[r-1][c-1],
    dp[r+1][c-1]
)
```

其中越界前驱不能参与最大值比较。

最终答案：

```text
max(dp[r][W-1])
```

### 5. 本题复习关键词

- 复杂题先拆成两个独立阶段
- 零填充只用于卷积取图像值
- 路径越界不是合法的零分路径
- 最大值 DP 注意负数
- 缓存哨兵不能与合法答案冲突
- 记忆化 DFS 与递推 DP 可以相互翻译

## 四、第 3 题：大模型分词

### 1. 题型识别

需要使用词元表完整覆盖字符串，得分由两部分组成：

```text
所有词元的置信度之和
+
所有相邻词元的转移分数之和
```

这不是普通的“单维字符串划分 DP”，因为选择当前词元时，得分还与相邻词元有关。

### 2. 我的第一版思路

我已经想到：

- 用哈希表保存词元置信度；
- 用哈希表保存转移得分；
- 从字符串右端枚举最后一个词元；
- 使用 DFS 求最大划分得分。

方向是正确的，但第一版没有通过，暴露出了几个重要问题。

### 3. 第一版没有掌握或出错的地方

#### 错误一：转移表的数据结构无法保存一对多关系

第一版使用：

```java
Map<String, Pair<String, Integer>> transitions;
```

它只能为一个前驱词元保存一个后继词元。如果存在：

```text
a -> b
a -> c
```

后插入的数据会覆盖前一条数据。

应使用嵌套哈希表：

```java
Map<String, Map<String, Integer>> transitions;
```

含义为：

```text
前驱词元 ->（后继词元 -> 转移得分）
```

构建方式：

```java
transitions
    .computeIfAbsent(pre, key -> new HashMap<>())
    .put(next, score);
```

#### 错误二：`substring` 左闭右开，端点处理错误

Java：

```java
text.substring(start, end)
```

截取的是：

```text
[start, end)
```

第一版使用 `substring(j, i)`，但状态又把 `i` 当作最后字符下标，导致 `text[i]` 没有被包含，而且当词元从下标 `0` 开始时也可能漏枚举。

更清晰的做法是始终使用“前缀长度”：

```text
end 表示前 end 个字符，即 text[0,end)
```

当前词元统一写成：

```java
text.substring(start, end);
```

当 `end == 0` 时，表示空前缀已经完整切分。

#### 错误三：第一版遗漏了词元自身的置信度

第一版更新结果时只加了转移分数：

```java
dfs(...) + score
```

但题目总分还必须包含每个词元的置信度：

```java
preScore + tokens.get(current) + transitionScore
```

这是一个非常关键的读题遗漏：建立状态后，还要逐项核对题目给出的得分公式，确认每一项都进入转移方程。

#### 错误四：无法切分与合法负分没有区分

第一版使用 `Integer.MIN_VALUE` 表示不可达，但直接与其他分数相加可能溢出。

正确做法：

```java
private static final int NEG_INF = Integer.MIN_VALUE / 4;
```

并在加法之前判断：

```java
if (preScore == NEG_INF) {
    continue;
}
```

这样可以明确区分：

- 合法方案，即使总分可能是负数；
- 无法完整切分的非法状态。

#### 错误五：没有记忆化，存在大量重复计算

状态不只由 `end` 决定，还由右侧相邻词元 `next` 决定：

```text
dfs(end, next)
```

相同状态会通过不同递归路径重复出现，因此需要缓存：

```java
Map<String, Integer> memo;
```

缓存键可以是：

```java
end + "#" + next
```

更工程化的写法可以给词元编号，使用二维数组缓存，避免频繁拼接字符串。

#### 易混点：递归参数中的 `next`

从右往左切分时：

- `current` 是本次选择的词元；
- `next` 是它右边已经确定的词元；
- 查找的是 `transition(current, next)`；
- 继续递归时，`current` 会成为更左侧词元的 `next`。

这也是为什么状态不能只写成 `dfs(end)`：相同前缀在右侧词元不同的情况下，后续转移得分可能不同。

### 4. 最终状态设计

```text
dfs(end, next) =
将 text[0,end) 完整切分，并且其右侧相邻词元为 next 时，
能够获得的最高分
```

枚举当前最后一个词元：

```text
current = text[start,end)
```

转移：

```text
dfs(end,next) =
max(
    dfs(start,current)
    + confidence(current)
    + transition(current,next)
)
```

初始调用：

```java
dfs(text.length(), "")
```

空字符串表示最右侧没有下一个词元，因此不计算转移分数。

### 5. 本题新掌握的 Java API

```java
map.computeIfAbsent(key, k -> new HashMap<>())
map.getOrDefault(key, defaultValue)
```

但需要注意：`getOrDefault` 只适用于外层 Map 已经存在的情况，因此通常先写：

```java
Map<String, Integer> scores = transitions.get(current);
if (scores != null) {
    score = scores.getOrDefault(next, 0);
}
```

### 6. 本题复习关键词

- 字符串划分 DP
- 相邻项影响得分时，状态必须记录相邻项
- 一对多关系使用嵌套 Map
- `substring(start,end)` 左闭右开
- 不可达状态使用 `NEG_INF`
- 加分前先判断前驱是否合法
- 不能漏掉词元自身置信度
- 记忆化避免重复计算

## 五、第 4 题：大模型训练显存优化

### 1. 题型识别

每个张量有三种操作：

- 不优化；
- Swap，释放 `s[i]`，代价 `a[i]`；
- 重计算，释放 `s[i]`，代价 `b[i]`。

要求释放显存不少于 `target`，总代价最小。

由于 Swap 和重计算释放的显存相同，而目标只关心总代价，所以可以先预处理：

```java
cost[i] = Math.min(a[i], b[i]);
```

于是问题转化为：

- 每个张量选或不选；
- 选中后释放 `s[i]`，付出 `cost[i]`；
- 至少释放 `target`；
- 求最小代价。

这就是 0-1 背包的变形。

### 2. 我的第一版思路

第一版记忆化搜索基本正确：

```text
dfs(i, remain) =
从 0~i 的张量中选择，还需要至少释放 remain 显存时的最小代价
```

三种原始操作经过预处理后只剩：

- 不选当前张量；
- 选择当前张量并支付 `min(a[i],b[i])`。

这说明我已经能够识别 AI 包装下的传统背包模型。

### 3. 从 DFS 翻译成二维递推时的错误

#### 错误一：状态定义和转移方向混在了一起

我定义：

```text
dp[i][j] = 前 i 个张量释放 j 显存的最小代价
```

但代码写成：

```java
dp[i + 1][j] = Math.min(
    dp[i][j],
    dp[i][next] + a[i]
);
```

这里出现了三个问题：

1. 选择当前张量后应该更新 `dp[i+1][next]`，而不是 `dp[i+1][j]`；
2. 转移来源应该是当前状态 `dp[i][j]`，而不是未来状态 `dp[i][next]`；
3. 没有把“不选”和“选”分别更新到各自的目标状态。

#### 错误二：没有理解推送式更新为什么要取最小值

推送式写法是：

```java
dp[i + 1][j] = Math.min(dp[i + 1][j], dp[i][j]);

int next = Math.min(target, j + s[i]);
dp[i + 1][next] = Math.min(
    dp[i + 1][next],
    dp[i][j] + cost[i]
);
```

不能直接赋值，因为同一个目标状态可能由多个来源到达。例如：

```text
释放量 10
```

可能来自：

- 原来释放 7，再选择大小 3 的张量；
- 原来释放 6，再选择大小 4 的张量；
- 原来已经释放 10，本轮不选。

这些路径代价不同，所以必须保留其中的最小值。

#### 对“传统 0-1 背包好像不需要取最小值”的理解

传统拉取式写法看起来像：

```java
dp[i + 1][j] = Math.min(
    dp[i][j],
    dp[i][j - s[i]] + cost[i]
);
```

它实际上同样取了最小值，只是把所有来源集中写在目标状态右侧，所以不需要多次更新同一个格子。

区别是：

- 推送式：从一个已知状态向多个目标状态更新；
- 拉取式：站在目标状态，收集所有可能的来源。

### 4. “至少 target”的封顶技巧

如果实际释放量超过 `target`，无需记录具体超过多少。可以统一压缩为：

```java
int next = Math.min(target, j + s[i]);
```

因此：

```text
状态 target 表示已经释放至少 target
```

这是处理“至少达到某个目标”时非常实用的状态压缩技巧。

### 5. 正确的二维推送式 DP

状态：

```text
dp[i][j] = 使用前 i 个张量，释放量为 j 的最小代价
```

其中 `j == target` 表示释放量不少于目标。

初始化：

```text
dp[0][0] = 0
其他状态 = INF
```

转移：

```java
// 不选
dp[i + 1][j] = Math.min(dp[i + 1][j], dp[i][j]);

// 选
int next = Math.min(target, j + s[i]);
dp[i + 1][next] = Math.min(
    dp[i + 1][next],
    dp[i][j] + cost[i]
);
```

### 6. 压缩为一维数组

```java
int[] dp = new int[target + 1];
Arrays.fill(dp, POS_INF);
dp[0] = 0;

for (int i = 0; i < n; i++) {
    for (int j = target; j >= 0; j--) {
        int next = Math.min(target, j + s[i]);
        dp[next] = Math.min(dp[next], dp[j] + cost[i]);
    }
}
```

必须倒序遍历，原因是每个张量只能使用一次。若正序遍历，当前张量刚更新出的状态可能在同一轮再次参与转移，相当于重复使用同一个张量。

#### 关于是否可以省略非法状态判断

如果使用：

```java
POS_INF = Integer.MAX_VALUE / 2;
```

并且题目保证累计代价不会接近这个值，那么：

```java
POS_INF + cost
```

仍然足够大，通常不会更新出错误答案，此时可以省略：

```java
if (dp[j] == POS_INF) continue;
```

但这依赖于：

- `INF + cost` 不溢出；
- `INF` 大于所有合法答案。

因此竞赛中可以简化，但必须清楚简化成立的前提。

### 7. 本题复习关键词

- 0-1 背包最小化
- 两种操作效果相同，可先取最小代价
- “至少”目标使用封顶状态
- 推送式：从来源更新目标
- 拉取式：从目标枚举来源
- 多条路径到达同一状态时必须取最优值
- 一维压缩必须倒序
- `INF` 加法要防溢出

## 六、第 5 题：YOLO Anchor 聚类

### 1. 题型识别

题目要求按照指定规则对检测框 `(width,height)` 进行 K-Means 聚类：

1. 选择前 `K` 个检测框作为初始中心；
2. 将每个检测框分配给距离最近的中心；
3. 使用聚类内宽、高的平均值更新中心；
4. 重复迭代；
5. 中心变化足够小时提前结束；
6. 按题目要求排序输出中心。

本题主要考查**按照题意进行多轮模拟**，不要求推导 K-Means。

### 2. 我的第一版完成情况

我已经完成了主要框架：

- 使用 `Box` 保存检测框；
- 使用 `Center` 保存中心和聚类中的检测框；
- 初始化前 `K` 个中心；
- 编写 IoU 距离函数；
- 编写分配和中心更新逻辑；
- 计算 `change`；
- 最后排序输出。

整体算法流程已经搭好，问题主要集中在几个很小但会直接破坏答案的实现细节。

### 3. 第一版的关键错误

#### 错误一：找到更小距离后，没有更新 `minDis`

第一版：

```java
if (distance < minDis) {
    index = i;
}
```

这里只更新了中心编号，没有更新当前最小距离。由于 `minDis` 一直是正无穷，之后遍历到的每个中心都会满足条件，最终检测框几乎总会被分配给最后一个中心。

正确写法：

```java
if (distance < minDis) {
    minDis = distance;
    index = i;
}
```

这是典型的“维护最优值时，只更新答案下标却忘记更新比较值”。

#### 错误二：每轮开始前没有清空聚类

`center.cluster` 保存的应该是**当前轮**的分配结果。第一版没有清空，导致上一轮的检测框继续保留，聚类样本不断累积，后续计算的平均中心错误。

每轮分配前必须：

```java
for (Center center : centers) {
    center.cluster.clear();
}
```

需要区分：

- 中心坐标：继承上一轮结果；
- 聚类成员：每轮重新分配，必须清空。

#### 错误三：最终排序方向写反

题目要求面积从大到小，但第一版比较器使用：

```java
return area1 - area2;
```

这是从小到大。

正确写法：

```java
return Long.compare(area2, area1);
```

面积相同后，宽和高也要按照题目要求继续比较，并仔细确认升序还是降序。

### 4. 其他潜在风险

#### 使用 `long` 防止乘法和求和溢出

面积、交集和宽高总和都可能超过 `int`：

```java
long area1 = (long) w1 * h1;
long intersection =
        (long) Math.min(w1, w2) * Math.min(h1, h2);
```

强制转换必须放在乘法之前，否则两个 `int` 会先发生溢出，再转换为 `long`。

#### IoU 必须进行浮点除法

```java
double iou = (double) intersection / (union + 1e-16);
```

如果分子、分母都是整数，会发生整数除法，大多数 IoU 会变成 `0`。

#### 空聚类必须保留原中心

如果某个中心本轮没有分配到任何检测框：

```java
if (cluster.isEmpty()) {
    continue;
}
```

不能除以 `0`，也不能随意把中心改为 `(0,0)`。

#### 平均值取整

如果题目要求向下取整，并且宽高都是正整数：

```java
int newWidth = (int) (sumWidth / count);
```

整数除法正好满足向下取整要求。

### 5. 本题的实现模板

```text
读取数据
→ 建立 Box 和 Center
→ 使用前 K 个 Box 初始化中心
→ 进入迭代
    → 清空各中心的本轮聚类
    → 为每个 Box 找最近中心
    → 将 Box 分配到对应聚类
    → 根据聚类成员更新中心
    → 累加新旧中心变化量
    → 判断是否收敛
→ 按规定排序
→ 输出
```

### 6. 对 K-Means 的理解

K-Means 的核心就是重复执行两个步骤：

- 分配：每个样本进入距离最近的聚类；
- 更新：使用聚类中的样本重新计算中心。

这道题给出了初始化方式、距离公式、中心更新规则和终止条件，所以即使此前没有系统学习 K-Means，也可以通过耐心读题完成。

了解 K-Means 的基础知识不是完成本题的绝对前提，但可以帮助我更快识别整体框架，并主动检查“每轮清空、重新分配、更新中心、判断收敛”等关键步骤。

### 7. 本题复习关键词

- K-Means 模拟
- 初始化—分配—更新—收敛
- 每轮清空聚类成员
- 维护最小值时同步更新值和下标
- IoU 浮点除法
- `long` 防止乘法溢出
- 空聚类保留旧中心
- Comparator 检查排序方向

## 七、五道题暴露出的共性问题

### 1. 状态定义还需要更加精确

我经常已经知道“大概用 DP”，但状态中的每个词还不够严谨，例如：

- `j` 表示“恰好损失为 j”，还是“不超过 j”？
- `target` 表示原始目标，还是尚未完成的剩余目标？
- 字符串端点表示下标，还是前缀长度？
- 当前状态是否需要记录前一个或后一个词元？

以后写 DP 前，先完整写一句：

> `dp[i][j]` 表示________。

并检查：

- 每个维度是否足够决定后续转移；
- 是否混用了下标和长度；
- 最终答案应该取某一个状态，还是一组状态的最值。

### 2. 对“不可达状态”的处理不稳定

求最小值时：

```text
非法状态 = POS_INF
```

求最大值时：

```text
非法状态 = NEG_INF
```

不能依赖数组默认值 `0`，因为 `0` 往往会被误认为合法答案。

同时要检查：

- `INF + cost` 是否溢出；
- 哨兵值是否可能与合法答案相同；
- 非法状态是否参与了转移。

### 3. 题目中的“至多、至少、恰好”需要特别标记

这些词直接决定状态和答案：

| 题目要求 | 常用处理 |
|---|---|
| 恰好达到 `T` | 读取 `dp[T]` |
| 不超过 `T` | 在 `0...T` 中取最优 |
| 至少达到 `T` | 将超过 `T` 的状态封顶到 `T` |

### 4. 从 DFS 翻译成递推时容易把方向写反

翻译前应先判断自己使用哪一种写法：

- 推送式：从 `dp[i][j]` 出发，更新下一状态；
- 拉取式：计算 `dp[i+1][j]` 时，枚举它的来源。

不能在同一个转移式里混合两种思考方向。

### 5. 复杂题拆步骤的能力正在形成

最大能量路径和 K-Means 都说明，遇到长题面时可以先列流程：

```text
输入
→ 建模
→ 预处理
→ 核心迭代/DP
→ 边界处理
→ 排序和输出
```

题目越长，越不应该边读边直接写完整代码。先拆成函数或阶段，能显著减少遗漏。

### 6. 小实现错误会摧毁正确的大思路

这一天出现的典型细节错误包括：

- `substring` 端点少一个字符；
- 忘记加词元置信度；
- Map 结构导致数据被覆盖；
- 找最小距离时忘记更新 `minDis`；
- 每轮迭代忘记清空旧聚类；
- Comparator 排序方向写反；
- 注释写“最小值”，代码实际求最大值。

这些错误说明：算法思路正确不代表代码一定正确。完成代码后需要进行一次独立的“实现检查”，不能只重新看总体思路。

## 八、以后每道题的提交前检查清单

### 1. 读题检查

- [ ] 求最大值还是最小值？
- [ ] 是恰好、至多还是至少？
- [ ] 每个元素能选几次？
- [ ] 是否必须选择？
- [ ] 是否存在负数、小数、空集合或不可达情况？
- [ ] 输出排序是升序还是降序？有无次级排序规则？

### 2. 状态检查

- [ ] 我能否用一句完整的话定义 `dp/dfs`？
- [ ] 状态是否包含决定后续得分所需的全部信息？
- [ ] 下标与前缀长度是否混淆？
- [ ] 初始状态是否只有合法起点？
- [ ] 非法状态使用了正确的 `INF`？
- [ ] 最终答案是一个状态还是多个状态的最值？

### 3. 转移检查

- [ ] 当前写的是推送式还是拉取式？
- [ ] 选与不选分别转移到哪里？
- [ ] 多条路径到达同一状态时是否取了最优值？
- [ ] 一维 0-1 背包是否倒序遍历？
- [ ] 是否漏加题目得分公式中的某一项？
- [ ] 不可达状态是否被错误地用于转移？

### 4. Java 实现检查

- [ ] `substring(start,end)` 是否按左闭右开理解？
- [ ] Map 是否真的能保存题目要求的一对多关系？
- [ ] 整数除法和浮点除法是否符合预期？
- [ ] 乘法前是否转换为 `long`？
- [ ] Comparator 是否可能溢出，方向是否正确？
- [ ] 循环中的临时容器是否应该每轮清空？
- [ ] 更新最优下标时，是否也更新了最优值？

### 5. 手动样例检查

至少自己构造以下边界：

- [ ] 只有一个元素或一层；
- [ ] 刚好达到目标；
- [ ] 超过目标；
- [ ] 无法达到目标；
- [ ] 所有答案为负数；
- [ ] 多条路径到达同一个状态；
- [ ] 空聚类或空转移表；
- [ ] 排序主关键字相同，需要比较次关键字。

## 九、Day 1 最终总结

今天五道题最大的收获，不只是完成了 DP、字符串划分和 K-Means，而是开始建立一套面对华为 AI 岗编程题的通用方法：

1. 先去掉 AI 背景，识别传统算法模型；
2. 将长题面拆成若干明确步骤；
3. 用一句完整的话定义状态或数据结构；
4. 明确合法起点和不可达状态；
5. 再决定使用 DFS、拉取式递推还是推送式递推；
6. 最后专门检查端点、初始化、更新变量、清空容器和排序方向。

目前我的主要问题已经不是“完全没有算法思路”，而是：

- 状态含义有时不够精确；
- 从递归翻译为递推时容易混淆转移方向；
- 对不可达状态和边界值处理不够稳定；
- 正确的大框架中仍会出现关键的局部实现错误。

这些问题都可以通过“错因复盘 + 提交前检查清单”持续改善。下一次遇到相似题目时，目标不是背出原代码，而是能够主动问自己：

> 状态到底表示什么？非法状态是什么？同一状态是否有多个来源？每一轮有哪些数据必须重置？题目公式中的每一项是否都已经进入代码？
