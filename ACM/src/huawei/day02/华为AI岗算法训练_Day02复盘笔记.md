## 2. 核心知识

### 2.1 概念与解决的问题

这 5 道题虽然使用了 Attention、MoE、终端识别、流量分析和基站优化等 AI 背景，但核心考点主要是传统编程能力：

| 题目 | 表层背景 | 实际考点 | 本题最值得记住的内容 |
|---|---|---|---|
| 大模型 Attention 模块开发 | Transformer Attention | 矩阵乘法、转置、按行归一化、公式模拟 | 按计算图逐步实现，并持续检查矩阵形状 |
| 终端款型聚类识别 | 终端型号识别 | 四维 KMeans、停止条件、排序 | 更新完全部质心后，才能统一判断是否收敛 |
| 网络流量分析 | 流量特征聚类 | 三维 KMeans、固定轮数、格式化输出 | 题目规定固定迭代次数时，不要擅自提前结束 |
| 基站聚类分析 | 无线网络优化 | 二维 KMeans、轮廓系数、银行家舍入 | “遍历其他元素”要完整遍历后 `continue` 跳过自身；最终簇必须和最终质心一致 |
| MoE 场景路由优化 | 专家路由与 NPU 分组 | 间接排序、Top-P、Top-K、编号映射 | 按概率排序时排序编号，而不是把编号与概率拆散 |

最重要的总体认识是：**AI 岗编程题不一定要求推导复杂模型，很多题是在考能否把题目给出的 AI 计算流程准确翻译为程序。**

### 2.2 在本次题单中的数据流

五道题可以归纳为三类数据流：

1. **公式模拟型：Attention**

   `输入矩阵 → Q/K/V → 注意力得分 → 归一化 → 输出矩阵 → 汇总答案`

2. **迭代更新型：三道 KMeans**

   `读取样本 → 初始化质心 → 清空簇 → 分配样本 → 更新全部质心 → 判断停止 → 统计或评价结果`

3. **筛选排序型：MoE**

   `专家概率 → 各 NPU 代表概率 → 选 P 个 NPU → 收集候选专家 → 选 K 个专家 → 按输出规则重排`

做题时先画出这样的数据流，再决定数组和类如何设计，代码会明显更稳定。

### 2.3 与 Java / 既有知识的联系

- Attention 是二维数组与矩阵乘法的综合应用。
- KMeans 是“模拟 + 循环不变量 + 状态更新”，不是动态规划。
- MoE 是排序题，关键是 `id` 与 `value` 的绑定，和“按成绩排序后输出原学号”完全相同。
- `Double.POSITIVE_INFINITY` 适合初始化待求的最小值。
- 只比较欧氏距离大小时，可以比较距离平方，省去 `Math.sqrt`。
- `printf("%.2f", x)` 负责显示两位小数；若题目明确要求 `HALF_EVEN`，应使用 `BigDecimal`。
- `%` 是格式化字符串中转换说明符的起点，例如 `%d`、`%s`、`%.2f`、`%n`；输出百分号本身用 `%%`。

## 3. 实现过程

### 3.1 大模型 Attention 模块开发

#### 已完成的思路

你成功把计算过程拆成了以下步骤：

1. 构造输入矩阵 `X` 和权重矩阵 `W`；
2. 计算 `QKV = XW`；
3. 计算 `QK^T`；
4. 除以 `sqrt(h)`；
5. 对每一行进行题目规定的归一化；
6. 计算输出 `Y`；
7. 汇总并四舍五入输出。

这份实现已经在 CodeFun 全部通过，说明主数据流和边界处理正确。

#### 学到的核心方法

遇到矩阵公式时，不要一口气写完整表达式，而要把每个中间结果单独命名，并标注形状：

| 矩阵 | 形状 |
|---|---|
| `X` | `n × m` |
| `W` | `m × h` |
| `Q/K/V = XW` | `n × h` |
| `QK^T` | `n × n` |
| `A` | `n × n` |
| `Y = AV` | `n × h` |

矩阵乘法成立的条件是：左矩阵的列数等于右矩阵的行数。形状检查可以在写循环前就发现大量下标错误。

#### 可继续优化

- 矩阵乘法中的 `n、m、h` 可以改成 `rows、cols、common`，降低维度混淆。
- 维度不合法时，不宜静默返回 `null`，可以直接抛出异常或在调用前保证合法。
- 只为计算 `QK^T` 时，可以用下标访问避免真的构造转置矩阵。
- 本题数据还有进一步的数学化简：因为 `X` 的每一行相同，所以 `Q/K/V` 的每一行也相同，注意力权重最终均匀。不过考试中先写通用模拟通常更稳，确认正确后再考虑化简。

### 3.2 终端款型聚类识别

#### 正确框架

你通过 `Terminal` 保存四维特征，通过 `Center` 同时保存质心和所属簇。这个建模很好地对应了题目对象，使“分配”和“更新”更直观。

KMeans 的标准骨架是：

```java
initializeCenters();
for (int round = 0; round < maxRounds; round++) {
    clearClusters();
    assignSamples();

    boolean allStable = true;
    for (Center center : centers) {
        if (center.cluster.isEmpty()) continue;
        Point next = mean(center.cluster);
        if (distance(center.point, next) >= EPS) {
            allStable = false;
        }
        center.point = next;
    }

    if (allStable) break;
}
```

#### 第一版暴露的问题

1. **特征下标写错**

   读取第 `i` 个终端的第 `j` 个特征时，应该写 `features[j]`，第一版写成了 `features[i]`。这说明嵌套循环中“对象编号”和“对象内部维度”还需要刻意区分。

2. **在单个质心内部提前 `break`**

   一个质心不再移动，不代表全部质心均已稳定。必须先更新完所有质心，再判断“是否所有质心都稳定”。

3. **没有处理空簇**

   空簇没有可用于求平均值的样本，应保留旧质心并跳过更新。对 `double` 做除零通常不会直接抛异常，而会得到 `NaN` 或 `Infinity`，这些值随后会污染距离比较。

4. **排序方向与题目要求相反**

   题目要求簇大小升序，而 `o2.size() - o1.size()` 是降序。排序方向和最终输出属于题目正确性的一部分。

### 3.3 网络流量分析

#### 已掌握的内容

这道题与上一题本质相同，但输入和停止规则不同：

- 特征从四维变成三维；
- 初始质心单独给出；
- 严格执行 `T` 轮，不需要收敛判断；
- 空簇保留原质心；
- 按输入顺序输出质心；
- 每个坐标保留两位小数。

这说明复用模板时，不能机械复制，必须重新核对题目的五个约定：**初始化、距离、空簇、停止、输出。**

#### 新增的 Java 知识

```java
System.out.printf("%.2f %.2f %.2f%n", x, y, z);
```

- `%.2f`：以浮点格式输出，保留两位小数，并按格式化规则舍入显示；
- `%n`：输出跨平台换行；
- 格式化不会改变变量本身的数值，只影响显示结果。

若只是比较两个样本谁离质心更近，可以直接使用距离平方：

```java
double dx = a.x - b.x;
double dy = a.y - b.y;
double distanceSquared = dx * dx + dy * dy;
```

这样避免了 `Math.pow` 和 `Math.sqrt`。

### 3.4 无线网络优化中的基站聚类分析

#### 本题真正的难点

本题不只是普通 KMeans，难点集中在两个地方：

1. KMeans 结束后的簇是否与最终质心一致；
2. 正确实现轮廓系数。

对样本 `i`：

- `a(i)`：它到同簇内其他样本的平均距离；
- `b(i)`：它到每个其他簇的平均距离中的最小值；
- `s(i) = (b(i) - a(i)) / max(a(i), b(i))`。

#### 第一版暴露的问题

1. **把“跳过自身”写成了“终止循环”**

   错误模式：

   ```java
   for (int j = 0; j < size && j != i; j++)
   ```

   一旦 `j == i`，循环直接结束，`i` 后面的元素全部没有遍历。正确写法是完整遍历，再跳过自身：

   ```java
   for (int j = 0; j < size; j++) {
       if (j == i) continue;
       // 处理其他样本
   }
   ```

   “遍历除某个元素以外的所有元素”通常使用 `continue`，而不是把排除条件写进循环继续条件。

2. **收敛标志的语义写反**

   第一版在“存在质心移动超过阈值”时设置 `flag = true`，随后却在 `flag` 为真时退出，这会让算法通常第一轮就结束。

   更稳的命名方式是：

   ```java
   boolean allStable = true;
   if (change > EPS) allStable = false;
   if (allStable) break;
   ```

   变量名直接表达逻辑量词，可以减少“存在一个变化”与“全部稳定”的混淆。

3. **最终质心与簇成员不同步**

   每轮顺序是“根据旧质心分配 → 计算新质心”。如果正好因为达到最大轮数退出，当前簇仍是按旧质心分配的，而中心已经更新。此时若直接计算轮廓系数，就会使用过期的簇。

   因此，只要后续答案依赖最终簇成员，KMeans 结束后就应该用最终质心再执行一次：

   `清空簇 → 重新分配样本`

4. **没有按要求使用银行家舍入**

   `printf("%.2f")` 不等价于明确指定 `HALF_EVEN`。题目严格要求银行家舍入时，可以写：

   ```java
   static String formatHalfEven(double value) {
       return BigDecimal.valueOf(value)
               .setScale(2, RoundingMode.HALF_EVEN)
               .toPlainString();
   }
   ```

   `HALF_EVEN` 在小于一半时舍去、大于一半时进位；只有恰好位于一半时，才选择使保留位为偶数的方向。例如保留两位时，`2.665 → 2.66`，`2.675 → 2.68`。

5. **可读性会影响正确性**

   第一版先把 `-a` 暂存在成员变量 `s` 中，之后再与 `b` 合成轮廓系数，数学上可以成立，但含义隐蔽。更清晰的方式是分别使用局部变量 `a、b、silhouette`。这不是单纯的“代码好看”，而是在降低后续改错难度。

#### 对错误性质的重新认识

这些问题不全是工程细节：循环提前终止、收敛条件反转、使用过期簇，都会直接改变算法结果，属于逻辑正确性问题。工程能力的价值就在于让这些逻辑关系在代码中清晰可见。

### 3.5 大模型训练 MoE 场景路由优化算法

#### 卡住的位置

你已经完成了输入校验、专家分组和每张 NPU 的代表概率，但卡在：

1. 如何选出代表概率最大的 `P` 张 NPU；
2. 如何从这些 NPU 中选出概率最大的 `K` 个专家。

#### 没做出来的根本原因

缺少的不是 MoE 知识，而是一个通用编程技巧：**按值排序，同时保留原编号。**

如果直接排序概率数组，概率原来属于哪张 NPU、哪个专家的信息就丢失了。因此应排序编号，让比较器通过编号去查概率：

```java
Integer[] groupIds = new Integer[m];
for (int i = 0; i < m; i++) groupIds[i] = i;

Arrays.sort(groupIds, (id1, id2) -> {
    int cmp = Double.compare(representProbability[id2],
                             representProbability[id1]);
    return cmp != 0 ? cmp : Integer.compare(id1, id2);
});
```

这里：

- `groupIds` 中保存的是 NPU 组号；
- `representProbability[groupId]` 是排序依据；
- 概率降序，概率相同时组号升序；
- `int[]` 不能直接使用对象比较器，因此使用 `Integer[]` 或自定义对象。

选中一张编号为 `groupId` 的 NPU 后，它负责的专家编号区间为：

```text
[groupId * groupSize, (groupId + 1) * groupSize)
```

收集候选专家时保存的是**专家编号**，再用相同方式按 `probabilities[expertId]` 排序。选出前 `K` 个以后，还要按照题目要求将最终专家编号升序输出。这里存在两种不同排序：

- 选择阶段：按概率降序；
- 输出阶段：按专家编号升序。

#### 最重要的抽象

| 名称 | 含义 | 排序依据 |
|---|---|---|
| `groupId` | NPU 的组号 | 该组代表概率 |
| `expertId` | 全局专家编号 | 该专家自身概率 |
| 数组下标 | 查询概率的键 | 不应该因排序而丢失 |

以后看到“按某个属性排序，但最终返回原位置、原编号或原对象”，立即想到两种建模方式：

- 间接排序：排序 `id`；
- 绑定对象：定义 `(id, value)`。

## 4. 问题与修正

### 4.1 错误分类总表

| 错误类型 | 本次表现 | 原因 | 修正方法 |
|---|---|---|---|
| 下标语义混淆 | `features[i]` 与 `features[j]` 混用 | 没有区分样本编号和特征编号 | 写循环前标注每一层下标的含义 |
| 控制流错误 | `j != i` 写进循环条件 | 把“跳过”误写成“结束” | 完整遍历，使用 `continue` 排除自身 |
| 量词错误 | 有质心变化时反而停止 | 混淆“存在变化”和“全部稳定” | 使用 `allStable` 等语义明确的变量名 |
| 局部结论代替整体结论 | 一个中心稳定就 `break` | 没有先处理完所有质心 | 更新全部质心后统一判断 |
| 状态不同步 | 新质心配旧簇 | 忽略“分配”和“更新”的先后关系 | 结束后用最终质心重新分配一次 |
| 边界遗漏 | 空簇除以零 | 没有考虑某个中心无人归属 | 空簇保留旧质心并跳过更新 |
| 值与编号失联 | 不知如何选 NPU / 专家 | 只想到排序概率，没有保留来源 | 排序编号或使用 `(id, value)` 对象 |
| 输出契约遗漏 | 升降序、HALF_EVEN | 把输出当作计算后的附属步骤 | 单独列出排序、舍入、分隔符和换行要求 |

## 8. 从五道题提炼的方法论

### 方法一：先去掉 AI 包装，再识别基础题型

先问自己：如果把“Attention、终端、NPU、专家”等名词替换成普通数组，这题究竟是在做什么？

- Attention → 矩阵计算模拟；
- 三道聚类 → 迭代分配与更新；
- MoE → 分组、排序与 Top-K。

识别基础题型后，再把 AI 规则逐项加回来。

### 方法二：先写数据流，再写代码

用一行箭头列出阶段，并为每个阶段确认输入、输出和数据结构。这样可以防止把“分配”“更新”“评价”混在同一个循环里。

### 方法三：让变量名直接表达数学语义

优先使用：

- `allStable`，而不是 `flag`；
- `groupId`、`expertId`，而不是都叫 `index`；
- `sampleIndex`、`featureIndex`，而不是都叫 `i/j` 后不再区分；
- `distanceSquared`，而不是含义模糊的 `temp`。

变量名不是装饰，它能帮助检查逻辑量词、编号层级和状态含义。

### 方法四：区分“状态更新”与“由状态派生的数据”

质心是状态，簇成员是根据质心派生的数据。质心更新以后，旧簇不一定仍然正确。凡是程序中出现这种关系，都要问：**主状态变了，派生数据是否需要重新计算？**

### 方法五：把边界和输出纳入主算法

空簇、单元素簇、概率相同、达到最大轮数、排序方向、舍入方式都可能决定是否通过。写完主体循环后，应专门用检查清单验证这些条件。

### 方法六：遇到“按值排序、返回编号”，立即使用间接排序

不要移动值后再寻找它原来的位置。让编号作为排序对象，通过编号访问对应值，天然支持平局规则，也不会丢失身份。

### 方法七：复盘优先记录错误触发机制

只记“这里写错了”不够，要记清楚：

- 什么输入会触发错误；
- 错误为什么会发生；
- 应该使用哪种通用写法；
- 下一次写代码时用什么问题自检。

这比背一份正确代码更容易迁移到新题。
